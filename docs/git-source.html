Why the platform reads Git from inside the cluster

ArgoCD needs a Git repository to follow. By default that repository is platform/local-idp on a Gitea server running in the Kind cluster, not a repo on GitHub. This page shows how that works, what it buys, and what changes when you switch to GitHub.

Two ways to feed ArgoCD

The manifests are identical in both modes. Only the address ArgoCD reads from changes, and with it the path a commit travels.

The reason, in one line: with Gitea, the platform needs no account, no token, no public repo and no internet connection once the Helm charts are pulled (decision D4 in docs/decisions.md).

1Breaking the bootstrap cycle

ArgoCD installs Gitea, but ArgoCD reads everything from Gitea. seed-gitea.sh breaks that loop with one direct apply.

The order in the quick start

bootstrap-argocd.sh is the one Helm install. seed-gitea.sh is the one direct apply. Both are listed as exceptions in the GitOps rules; nothing else touches the cluster outside Git.

Public on purpose

The org and repo are created public, so ArgoCD and Backstage read them anonymously. No repository credential exists in ArgoCD.

2How a commit reaches the cluster

The same repo has two addresses: one for your laptop, reached through a port-forward, and one for everything inside the cluster.

Why clone URLs look wrong

Gitea's ROOT_URL is the in-cluster address, so the clone URL it shows does not resolve on your Mac. Browse at https://gitea.localtest.me/platform/local-idp instead.

Commits, not files

ArgoCD reads commits. An uncommitted edit under platform/ is invisible to it, which is why seed-gitea.sh refuses to run with a dirty tree.

3One switch, two values

set-git-source.sh rewrites two placeholders across platform/ and commits. There are no separate copies of the manifests per mode.

After switching to GitHub

Push to GitHub, then re-apply the plane roots (root-app.yaml, and self-service-app.yaml after phase 6) so ArgoCD reads them from the new address. The script prints both commands.

GitHub mode needs a public repo

ArgoCD has no repository credentials configured, and Backstage reads raw files anonymously. A private GitHub repo fails to sync.

4Gitea stays in both modes

The switch moves only the platform repo. The golden path depends on Gitea being a Git host the cluster can call and be called by.

Gitea or GitHub, side by side

Gitea is the default. GitHub is there for trying a remote source, not because the platform needs it.

Your local clone is the source of truth in both modes. The copy in Gitea is a delivery channel into the cluster. It is rebuilt from your clone every time you create a new cluster, so nothing is lost when it is destroyed.
