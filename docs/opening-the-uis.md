# Opening the UIs

Every platform UI is served through the Envoy Gateway at `https://<name>.localtest.me`. The name
resolves to 127.0.0.1 without touching `/etc/hosts`, and Kind maps host ports 80 and 443 into the
cluster.

Trust the local CA once per cluster, or the browser warns on every page:

```bash
./provision/trust-ca.sh --install
```

It trusts the cluster's root CA in your macOS login keychain (no sudo; macOS asks for your password
in a dialog). Restart the browser afterwards. `./provision/destroy.sh` removes it again.

## ArgoCD

**URL:** https://argocd.localtest.me

**Username:** `admin`

**Password:** generated by ArgoCD when it installs, and different for every cluster. Copy it to the
clipboard without printing it:

```bash
kubectl --kubeconfig ~/.kube/local-idp -n argocd get secret argocd-initial-admin-secret \
  -o jsonpath='{.data.password}' | base64 -d | pbcopy
```

Drop `| pbcopy` to print it instead. From a Devbox shell, `KUBECONFIG` is already set and
`--kubeconfig` can go.

Things to know:

- **Keep `argocd-initial-admin-secret`.** ArgoCD's getting-started guide says to delete it after the
  first login. Here the `gitea-config` seed Job reads it to mint Backstage's ArgoCD token, so
  deleting it breaks that on the Job's next run.
- **The password changes with every cluster.** After `destroy.sh` and a rebuild, read it again.
- **The `backstage` account** in the user list is a read-only API account for Backstage's ArgoCD
  plugin. It has a token and no password; you cannot log in as it.
- **Where to start:** `platform-foundation` and `platform-self-service` are the two App-of-Apps.
  `svc-<name>` Applications are generated by the `golden-path-services` ApplicationSet, one per
  service repo.

ArgoCD serves plain HTTP inside the cluster (`server.insecure`); TLS ends at the Gateway.

## The other UIs

| UI | URL | Sign in |
|---|---|---|
| Backstage | https://backstage.localtest.me | **Guest** button, no password |
| Gitea | https://gitea.localtest.me | Admin account from `platform/1-foundation/gitea/application.yaml` (`gitea.admin`), also in `Secret/gitea-seed-creds` in `gitea`. Public repos browse without signing in |
| Grafana | https://grafana.localtest.me | `admin` / `local-dev-only` (dev value, in the `kube-prometheus-stack` Application) |
| Argo Workflows | https://workflows.localtest.me | None: server auth mode |

Gitea's `ROOT_URL` is the in-cluster address `http://gitea-http.gitea.svc:3000/`, so the clone
URLs Gitea shows point there and do not resolve from your machine. Swap the host for
`gitea.localtest.me`.

All of these credentials are local dev values that exist only on your own cluster. See the Secrets
section of `AGENTS.md`.
